## 1. 배경: 왜 새 타깃이 필요한가

v1 승인 이미지(`approved-visual-v1.png`)는 빽빽한 식생, 수공예 랜드마크, 따뜻한 재질감의 미니チュ어 월드를 제시했다. 그러나 런타임 구현은 CSS/SVG 기술 제약 안에서 단순 실루엣 섬 + 넓은 빈 수면 + 존재감 없는 소형 캐릭터에 머물렀다. 유저가 체감한 갭의 본질:

| 층 | v1 레퍼런스 기대 | 런타임 실제 | 갭 심각도 |
|---|---|---|---|
| 캐릭터 | 표정·복장·도구가 읽히는 치비, 작업 중인 포즈 | 실루엣 수준 소형 도트, 동작 부재 | 심각 |
| 환경 밀도 | 식생·소품·건축이 빽빽한 미니チュ어 | 단색 지형 + 소품 3~5개 | 심각 |
| 움직임 | 월드 전체가 숨쉬는 느낌 | 수면 반짝임 + 캐릭터 미세 모션 | 심각 |
| 조명/분위기 | 따뜻한 태양광, 깊이 있는 그림자 | 평면적 단색 렌더링 | 중간 |
| 정보 통합 | 월드 오브젝트가 정보를 운반 | 월드 밖 일반 카드 UI | 중간 |

유저 기대치 재확인(2026-07-23): "아기자기하고 움직임이 추가된 RPG 게임 느낌" — 스타듀밸리·동물의숲·A Short Hike 계열의 cozy RPG 품질.

## 3. 층별 품질 기준

### 3.1 캐릭터

- 비율: 2.8~3.2등신 (DESIGN.md §7 유지). 머리 크고 몸 작은 치비이되, 유아·마스코트 처리 금지.
- 화면 존재감: 포커스 씬에서 캐릭터 높이가 섬 뷰포트 높이의 1/8 이상. 현재 런타임(1/20 이하) 대비 2.5배 이상 확대.
- 역할 가독성: 실루엣 + 복장 컬러 + 도구만으로 Code Engineer(고글·공구벨트·망치)와 QA Navigator(돋보기·클립보드·렌즈)가 즉시 구분되어야 한다. 색맹 시뮬레이션에서도 구분 유지.
- 애니메이션 최소 세트:
  - idle: 숨쉬기·깜빡임·머리카락/옷자락 흔들림 (3채널 이상, 2~4초 주기)
  - walk: 6프레임 이상 사이클, 좌우 반전 또는 4방향
  - task: §8 라이프사이클 매핑별 작업 애니메이션 (망치질, 돋보기 검사, 지도 펼치기, 등대 점등 등)
  - 반응: 유저가 섬 선택 시 캐릭터가 카메라 쪽을 보거나 손을 흔드는 1회성 리액션
- 금지: 금속 섀시, 화면 얼굴, 안테나, 로봇 관절 (§7 유지).

### 3.2 환경/월드

- 지형: 최소 2단 높이 변화(테라스·절벽·언덕). 단색 평면 지형 금지. 매트한 페인트 plaster 재질, 넓은 색면 + 절제된 라운딩.
- 식생: 나무·관목 최소 3종/섬, 바람 흔들림 애니메이션(2~4초 주기, 위상 오프셋으로 동기화 방지).
- 수면: 해안선 거품 애니메이션, 물고기 그림자, 잔물결, 정박 보트 상하 흔들림. 수면은 월드의 40% 이하로 유지(현재 ~65% → 축소).
- 건축: 창문이 개별적으로 발광/점멸, 문·간판·지붕 디테일, 섬당 최소 1개 시그니처 랜드마크(§6).
- 살아있는 소품: 굴뚝 연기, 깃발/빨랫줄 펄럭임, 갈매기, 나비, 구름 그림자 — 섬당 5종 이상. 타깃 `01`의 밀도를 하한으로 본다.
- 프로젝트 확장 시: 새 섬은 고유 지형+랜드마크 패밀리를 추가해야 하며, 기존 섬 리스킨 금지 (§6 유지).

### 3.3 움직임 어휘

- ambient: 저주파(2~6초 주기), 화면 밖 일시정지, reduced-motion 시 정지 포즈 유지 (§8 유지).
- lifecycle 이벤트: 데이터 변경 시 1회 재생, 상시 스크린세이버 아님 (§8 유지). 전환 240~420ms.
- 카메라: 섬 간 이동 시 팬+줌, 400~600ms ease-out. 월드 회전 금지(§4 카메라 계약 유지).
- 파티클: 연기·반딧불·물보라 — 화면당 동시 파티클 200개 상한, Save-Data 시 비활성화.
- "살아있음"의 판정 기준: 유저가 10초간 아무 입력 없이 화면을 볼 때, 최소 5개의 독립적 움직임 채널이 관찰되어야 한다.

### 3.4 조명/분위기

- 주간: 좌상단 태양광, 우하단 부드러운 접촉 그림자, 따뜻한 금색 하이라이트 (§4 유지).
- 야간(v2 범위 확정 시): 창문 앰버 불빛, 랜턴 코랄/골드, 달빛 은색 스파클 경로, 수면 반사 기둥. 타깃 `03` 기준.
- 포커스 씬: 선택 섬에 약간의 틸트시프트 피사계심도 느낌(수면 가장자리 블러)으로 미니チュ어감 강화.

### 3.5 정보 통합 (UI in World)

- 프로젝트 사실(이름·단계·성과·링크)은 시맨틱 HTML로 제공하되(§9 유지), 시각적으로는 월드 오브젝트로 표현: 선착장 표지판, 떠 있는 항해 일지, 게시판.
- 텍스트는 절대 래스터 아트에 베이킹 금지 (§10 유지). 모든 라벨은 DOM 오버레이 또는 런타임 렌더 텍스트.
- 포커스 링: 월드 스타일(거품/잉크 또는 잉크/코랄)의 visible focus (§10 유지).
- 현재 우측 대시보드 패널 → 월드 내 정보 오브젝트로 전환하되, 동일 데이터 소스·동일 링크 유지.

## 4. 현재 런타임 대비 갭 매트릭스 (구현 체크리스트 기준)

| 항목 | 현재 | 타깃 | 구현 수단 |
|---|---|---|---|
| 렌더링 | CSS/SVG 정적 | PixiJS 2D 캔버스, 스프라이트 애니메이션 | PixiJS v8, 텍스처 아틀라스 |
| 캐릭터 | 실루엣 도트 | 2.5배 확대, idle/walk/task 애니메이션 | 스프라이트 시트 (Aseprite 또는 동등 도구 저작) |
| 지형 | 단색 실루엣 | 2단 이상 높이, 재질감 있는 타일/레이어 | 레이어 PNG + 깊이 정렬 |
| 수면 | 반짝임만 | 거품·물고기·보트 흔들림 | 셰이더 또는 스프라이트 시퀀스 |
| 소품 | 3~5개/섬 | 5종 이상 살아있는 소품/섬 | 파티클 + 스프라이트 |
| 카메라 | 고정 | 팬/줌 400~600ms | PixiJS 카메라 트윈 |
| 정보 UI | 외부 카드 | 월드 내 오브젝트 + 시맨틱 HTML 병행 | DOM 오버레이 정합 |
| 모바일 | 카드 리스트 | 세로 항해 여정 (타깃 04) | 세로 스크롤 + 씬 전환 |

## 5. 자산 파이프라인

- 저작: 컨셉 아트 → 레이어 분리(지형/건축/식생/소품/캐릭터) → 스프라이트 시트(idle/walk/task) → 텍스처 아틀라스 → PixiJS 로드.
- 명명 규칙: `<project|shared>/<layer>/<asset>-<state>@<scale>x.png` (예: `booksalon/char/engineer-idle@2x.png`).
- 스케일: 2x 기준 제작, 1x/3x 파생. 레티나 대응.
- reduced-motion 폴백: 각 애니메이션의 정지 포즈 프레임 1장을 별도 추출.
- 프로젝트 확장 시: 새 섬 자산은 동일 파이프라인·명명 규칙을 따르며, 매니페스트(`presentation-manifest.v1.json`)에 등록.

## 6. 기술 결정

- 렌더러: PixiJS v8 (WebGL2, WebGPU 폴백). 3D 런타임 아님 — 기존 "3D 금지" 취지(월드 회전·카메라 틸트 방지)는 §4 카메라 계약으로 유지.
- 로딩: PixiJS 코어는 첫 페인트 이후 lazy import. 초기 HTML은 시맨틱 프로젝트 리스트(§9)로 즉시 렌더.
- 성능 예산: 미드레인지 기기 60fps, 프레임 16ms 이하, 텍스처 메모리 128MB 이하, 아틀라스 1장당 4096px 이하.
- 호환성: WebGL 미지원 시 정적 일러스트 + 시맨틱 리스트 폴백.
